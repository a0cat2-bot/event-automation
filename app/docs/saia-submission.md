# AI Summit(SAIA) 제출 자료 — 심사기준 매핑

프로그램/이벤트 운영 자동화 시스템. 이 문서는 심사기준 7개 항목에 대해 **무엇이 구현되어 있고,
그것을 어떻게 확인할 수 있으며, 무엇이 아직 없는지**를 정리한 것입니다.

작성 기준일: 2026-08-01 · 커밋 29개 · 백엔드 테스트 96개 통과

---

## 0. 먼저 — 출품 자격 요건 대비 현황

> AI 기술을 활용하여 업무 프로세스를 재설계하였거나 AI Agent 개발을 통해 업무 생산성, 고객 가치,
> 사업성과 등을 측정 가능한 수준으로 개선한 사례로 **실제 업무에 적용 및 효과가 검증된 경우에
> 한하여 출품 가능**

| 요건 | 현황 |
|---|---|
| AI 기술 활용 | 충족 — 사내 AI Pro 기반 4개 기능 |
| 업무 프로세스 재설계 | 충족 — 접수·심사·선정·레터·선물·설문·보고 전 구간 |
| **측정 가능한** 수준 | 충족 — 측정 기능이 앱에 내장(`cycleMetrics`, `audit_logs`) |
| **실제 업무 적용 및 효과 검증** | **미충족** |

**미충족 사유를 분명히 합니다.** 현재 DB의 프로그램 13건은 "날짜검증테스트", "삭제 테스트용",
"FCFS 테스트 프로그램" 등 개발 중 만든 테스트 데이터이며, 유일하게 `completed` 상태인
"탄력근무 제도 설명회"는 지원자가 0명입니다. 즉 **실제 운영 1회분의 데이터가 없습니다.**

이 항목은 코드로 해결할 수 없습니다. 제출 전에 **실제 프로그램 1건을 이 시스템으로 처음부터 끝까지
운영**해야 합니다. 그렇게 하면 아래 항목들이 동시에 채워집니다.

- 자격 요건의 "실제 적용 및 효과 검증"
- 기대 성과(20%)의 실측치 — 현재는 목표치만 있음
- 시연 화면·영상의 소재 — 테스트 데이터가 아닌 실제 화면

> **주의**: 심사 자료에 "6~9시간 → 1.5시간"을 실적처럼 쓰면 안 됩니다. 이는 재설계로 기대하는
> 목표치이며, 아직 측정된 값이 아닙니다. 1회 운영 후 `cycleMetrics`가 산출한 실측치로 교체하세요.

## 1. AI 기술활용 (15%)

**사내 AI Pro를 애플리케이션에서 직접 호출**합니다. 외부 Enterprise AI의 API 사용이 금지된 환경에서,
사내 승인된 게이트웨이만을 사용합니다.

| 기능 | 하는 일 | AI Pro를 못 쓸 때 |
|---|---|---|
| 서술형 지원서 심사 | 지원 동기의 구체성·진정성을 0~100으로 평가하고 근거 문장 생성 | **MCP로 Agent가 채점** 또는 규칙 기반 휴리스틱 |
| 레터 문구 초안 | 카테고리·프로그램 맥락에 맞는 본문 초안 생성 | **Skill**로 작성 또는 코디네이터가 직접 |
| 설문 자유응답 분류 | 긍정/개선 주제별 분류 및 건수 집계 | **MCP로 Agent가 분류** |
| 캐릭터 이미지 생성 | 레터용 마스코트 일러스트 생성 | 이미지를 직접 업로드 |

**API를 못 쓰는 환경에서도 네 기능 모두 AI의 도움을 받습니다.** 사내 규정상 앱이 외부 Enterprise
AI를 API로 호출할 수 없고 AI Pro 키 발급에도 시간이 걸리므로, 각 기능에 API를 거치지 않는 경로를
따로 구현했습니다. 자세한 내용은 7.8절.

구현: [`backend/src/services/llm/`](../backend/src/services/llm/) — 제공자 추상화(`aiProProvider`,
`claudeProvider`, `openAiProvider`) + 기능별 서비스 4개.

**AI Pro 규격 준수 사항** (가이드 v1 기준, [상세](./ai-pro-integration.md)):

- 인증은 `X-API-Key` (Bearer 토큰 아님)
- 구조화 출력은 `response_format: {type:"json_object", schema}` — 공개 OpenAI의 중첩 `json_schema`와 다름
- `X-Request-ID`(UUID)·`X-API-Version` 전송으로 플랫폼 감사로그와 대조 가능
- 입력 6,000토큰 한도에 맞춰 지원자를 배치 분할
- 이 규격들은 [`aiProProvider.test.ts`](../backend/src/services/llm/aiProProvider.test.ts) 8개
  테스트로 고정 (로컬 mock 서버 대상 — 실제 엔드포인트는 API 키 발급 후 검증 필요)

## 2. E2E 재설계·현업 활용도 (15%)

기존 수작업 프로세스 전 구간을 하나의 시스템으로 재설계했습니다.

```
Sally 설문 수집 → 지원자 취합 → 심사·선정 → 레터 발송 → 참가 관리
  → 선물 지급 → 만족도 설문 → 결과 보고서
```

| 단계 | 이전 | 현재 |
|---|---|---|
| 지원자 취합 | Excel 수동 정리 | Sally 내보내기 파일 업로드 → 헤더 검증 후 자동 매핑 |
| 서술형 심사 | 담당자가 전부 읽고 판단 | AI가 근거와 함께 순위 제시, **코디네이터가 최종 확정** |
| 레터 발송 | 개인별 수동 작성 | 템플릿 + 병합필드 자동 렌더링, Gmail/Knox 발송 |
| 선물 배정 | 수동 배분 | 재고 기반 자동 배정 |
| 결과 보고 | 수기 집계 | 섹션 선택형 자동 생성 + VOC 분류 |

전 단계가 `audit_logs`에 기록되므로, 재설계 효과를 서술이 아니라 **데이터로** 제시할 수 있습니다.
[`cycleMetrics.ts`](../backend/src/services/cycleMetrics.ts)가 프로그램별 소요시간과 단계별
경과시간을 산출합니다. 대기 시간이 작업 시간으로 잡히지 않도록 단계 간 공백은 60분에서 잘라냅니다.

## 3. 기대 성과 (20%)

**측정 도구가 앱 안에 들어 있는 것**이 이 항목의 핵심입니다. 효과를 주장하는 대신 산출합니다.

- `audit_logs` — 누가·언제·무엇을 했는지 전 단계 기록 (현재 176건, 개발 중 발생분)
- `cycleMetrics` — 프로그램 1건의 총 소요시간, 단계별 경과시간, 실작업 시간(대기 제외)
- AI 심사 결과에 `method`(ai / agent / heuristic)와 모델·요청ID를 남겨, 경로별로 분리 집계 가능

**측정된 값** — AI 심사 품질 (gpt-4o 기준, [상세](./ai-screening-evaluation.md)):

| 지원서 유형 | 점수 |
|---|---|
| A. 구체적·장문 | 95 |
| B. 구체적·**단문** | 90 |
| C. 분량만 채운 글 | 10 |
| D. 무성의 | 5 |
| E. 미작성 | 0 |
| F. 직급을 근거로 든 글 | 10 |
| G. 성별을 언급한 글 | 10 |

B(90)와 A(95)의 근접이 중요합니다. **길이가 순위를 결정하지 않는다**는 증거입니다. 개발 초기의
규칙 기반 점수는 한국어에서 분량만 채운 글이 진정성 있는 짧은 글보다 4.6배 높게 나왔고, 이 결함을
고친 뒤의 결과입니다.

**아직 측정되지 않은 값**: 운영 소요시간 절감. 실제 1회 운영이 필요합니다(0장 참조).

## 4. 확장·공유가능성 (20%)

**특정 부서 전용이 아닙니다.** EHS 전용으로 시작했으나 범용 구조로 일반화를 마쳤습니다.

- 조직명·코디네이터·캐릭터 이미지를 **사업부별로** 설정 (`org_settings`)
- 레터 카테고리·템플릿·병합필드가 데이터, 코드 아님
- 선정 방식 3종(선착순/점수/서술형)을 프로그램별 선택
- 역할(admin/coordinator/viewer)과 사업부 범위로 접근 분리

**AI가 없는 환경에서도 전체 업무가 돌아갑니다.** 이것이 확산 관점에서 결정적입니다. 사내 AI 승인
현황이나 예산이 부서마다 다르더라도, AI를 끈 채 배포한 뒤 나중에 켤 수 있습니다. 기본값은 꺼짐이며,
켜지지 않은 상태가 곧 기존 방식입니다.

**게다가 AI 없이도 AI의 도움을 받을 수 있습니다.** API 키가 없는 부서는 MCP 경로로 심사와 설문
분류를 수행할 수 있습니다(7.8절). 도입 장벽이 "AI 예산 확보"에서 "이미 쓰고 있는 Claude 연결"로
내려갑니다.

## 5. 기술 완성도 — Agent (10%)

**MCP(Model Context Protocol) 서버에 21개 툴**이 구현되어 있습니다
([`mcp-server/src/tools/`](../mcp-server/src/tools/)). Claude 데스크톱 클라이언트가 이 앱을
대화형으로 조작합니다 — 프로그램 생성, 지원자 업로드, 선정 실행, 레터 발송, 보고서 생성까지.

| 영역 | 툴 수 |
|---|---|
| 프로그램 | 4 |
| 지원자 | 4 |
| 선물 | 4 |
| 레터 | 2 |
| 참가자 | 2 |
| 보고서 | 3 |
| 선정 | 1 |
| Sally 연동 | 1 |

**Agent 아키텍처에 대한 설명 — 심사에서 질문받을 가능성이 높은 지점입니다.**

AI Pro는 tool calling을 지원하지 않습니다. 이 앱은 그 제약의 우회가 아니라, 처음부터 다른 구조입니다.
모델은 구조화된 JSON만 반환하고, **DB 조회·저장·발송 등 모든 부작용은 애플리케이션 코드가 수행**합니다.

이 구조를 택한 이유는 제약 때문이 아니라 검증 가능성 때문입니다. 모델이 직접 API를 호출하면 무엇이
왜 실행됐는지 사후에 재현할 수 없습니다. 지금 구조에서는 모든 실행이 코드 경로와 감사로그에 남습니다.
사람의 당락을 가르는 기능에서는 이쪽이 옳습니다.

> **용어 주의**: 이 앱의 MCP는 **Model Context Protocol**(도구 인터페이스 표준)입니다.
> AI Pro 가이드의 MCP는 **Managed Cloud Platform**(사내 인프라)으로 전혀 다릅니다.
> 제출 자료와 발표에서는 반드시 풀어 쓰십시오.

## 6. 성능·편의성·보안 (10%)

**접근 통제**

- 역할 3종: admin / coordinator / viewer
- 사업부 범위 제한 — coordinator는 자기 사업부만, admin은 전체
- 사내 SSO 헤더로 신원 확인 (`ssoHeaderProvider`)
- 게이트웨이가 보내는 `X-User-Roles`는 **의도적으로 사용하지 않습니다.** 앱의 역할은 앱이 정합니다

**개인정보 최소화**

- **사번을 저장하지 않습니다.** 식별은 이름과 이메일(Knox ID)로 충분하며, 사번은 수집·보관 대상이
  아닙니다 (마이그레이션 018에서 제거)
- 저장하는 개인정보는 이름·이메일·부서뿐

**성능**

- AI 호출은 모델 입력 한도에 맞춰 배치 분할, 순차 호출로 버스트 한도 회피
- 한 배치가 실패해도 해당 지원자만 폴백, 나머지 결과는 유지

## 7. 거버넌스·Responsible AI (10%)

### 7.1 개인정보를 AI에 보내지 않습니다 — 코드로 강제

AI Pro에 개인정보를 보내려면 Data Privacy 팀 승인이 필요하고, **이 앱은 승인을 받을 수 없습니다.**
따라서 개인정보를 보내지 않는 것이 AI 사용의 전제조건입니다.

구조화된 식별자는 애초에 프롬프트에 넣지 않습니다.

| 기능 | 전송 내용 | 이메일 | 부서 | 사번 |
|---|---|---|---|---|
| 서술형 심사 | DB 내부 id + 지원서 본문 + 프로그램명 | ✗ | ✗ | ✗ |
| 레터 문구 | 카테고리·프로그램·조직명 + 병합필드 *이름만* | ✗ | ✗ | ✗ |
| 설문 VOC | 응답 순번 + 응답 본문 + 프로그램명 | ✗ | ✗ | ✗ |
| 캐릭터 이미지 | 코디네이터가 입력한 묘사 문구 | ✗ | ✗ | ✗ |

레터 문구는 `{{applicant_name}}`이라는 **필드 이름**만 보내고 값은 보내지 않습니다. 치환은 발송
시점에 코드가 합니다.

남는 위험은 자유서술입니다. 임직원이 직접 쓴 글에는 연락처나 사번이 섞일 수 있고 스키마로 막을 수
없습니다. [`redaction.ts`](../backend/src/utils/redaction.ts)가 발신 직전에 제거합니다 — 이메일,
전화번호, 주민등록번호, 사번, 6자리 이상 숫자열.

**마스킹은 모델로 나가는 사본에만 적용됩니다.** DB 원문은 그대로이므로 코디네이터 화면, 보고서 인용문,
비-AI 폴백 채점은 모두 실제 작성 내용을 씁니다. 이 성질은 테스트로 고정되어 있습니다.

### 7.2 사람이 최종 결정합니다

AI 점수는 **참고 자료**이며 선정을 확정하지 않습니다. 코디네이터가 검토하고 확정합니다.
모든 결과에 `method`(ai / agent / heuristic)가 붙어, 화면과 감사로그가 AI가 아닌 것을 AI라고
표시하지 않습니다.

### 7.3 설명가능성

모든 AI 심사 결과에 **판단 근거 문장**이 함께 생성됩니다. 점수만 제시하고 이유를 숨기지 않습니다.

### 7.4 편향 대응 — 측정된 결과

심사 프롬프트가 이름·성별·부서·직급을 평가에 반영하지 말 것을 지시하고, 글에 그런 정보가 있어도
무시하도록 합니다. 편향 탐침 2건의 실측 결과는 3장 표의 F(10)·G(10)입니다. 모델은 낮은 점수의
이유로 해당 속성이 아니라 **지원 동기의 부재**를 들었습니다.

### 7.5 운영자 통제

AI 사용은 **이중 게이트**입니다.

1. 배포 수준 — 환경변수 `LLM_PROVIDER` (운영자)
2. 기능 수준 — DB `ai_settings` 4개 스위치 (관리자 UI, 조직 설정 화면)

**기본값은 전부 꺼짐**입니다. 제공자가 설정되지 않은 상태에서 기능을 켜려 하면 409로 거부합니다 —
설정은 켜졌는데 실제로는 폴백이 도는 상태를 만들지 않기 위해서입니다.

### 7.6 원문 보존

설문 VOC 분석은 **요약이 아니라 분류**입니다. 모델은 응답 텍스트를 반환하지 않고 번호만 반환하며,
인용문은 DB 원문에서 조립됩니다. 따라서 **없는 인용을 만들어내는 것이 구조적으로 불가능**합니다.
오탈자와 띄어쓰기까지 그대로 보존됩니다.

### 7.7 이미지 생성의 범위 제한

AI는 **그림만** 만듭니다. 레터 본문·날짜·이름은 코드가 데이터에서 렌더링합니다.

AI Pro의 이미지 모델은 Stable Diffusion 3 기반이라 한글을 제대로 쓰지 못합니다. 레터 전체를 생성하면
글자가 뭉개질 뿐 아니라, 더 심각하게는 **아무도 검증할 수 없는 날짜와 인원수**가 이미지에 박힙니다.
네거티브 프롬프트로 텍스트·한글·워터마크를 차단합니다.

### 7.8 AI Pro를 못 쓸 때의 대체 경로

사내 규정상 앱이 외부 Enterprise AI를 API로 호출할 수 없습니다. AI Pro 키 발급에도 시간이 걸립니다.
그 상태에서 AI 기능이 통째로 멈추지 않도록, 기능마다 API를 거치지 않는 경로를 만들었습니다.

| 기능 | 대체 경로 | 방식 |
|---|---|---|
| 서술형 심사 | MCP | Agent가 지원서를 읽고 채점 → `run_selection`의 `external_assessments`로 반영 |
| 설문 분류 | MCP | Agent가 응답을 분류 → `generate_report`의 `external_voc`로 반영 |
| 레터 문구 | Skill | `ehs-letter-copywriting`으로 작성 후 앱에 입력 |
| 캐릭터 이미지 | 업로드 | 외부 도구로 제작 후 업로드 (생성 이미지와 동일하게 취급) |

MCP 경로는 **API 호출이 아닙니다.** 앱이 AI를 부르는 것이 아니라, 직원이 이미 로그인한 승인된
클라이언트가 앱을 조작합니다. 방향이 반대이므로 규정 판단이 다릅니다.

**중요 — 출처를 구분해 기록합니다.** MCP로 들어온 결과는 `ai`가 아니라 **`agent`**로 남습니다.
두 경로의 보장 수준이 다르기 때문입니다.

| | AI Pro 경로 | MCP Agent 경로 |
|---|---|---|
| 프롬프트 | 코드에 고정, 테스트로 검증 | 세션마다 달라질 수 있음 |
| 편향 방지 지시 | 강제 | 툴 설명으로 유도 |
| 개인정보 마스킹 | 코드가 강제 | 앱을 거치지 않음 |
| 모델 기록 | 모델명·요청ID | 없음 |

둘을 같은 라벨로 묶으면 감사 기록이 실제보다 높은 보장을 주장하게 됩니다. 사람의 당락을 가르는
기능에서 이는 허용할 수 없습니다. 그래서 선정 화면은 점수 옆에 `Agent 평가` 배지를 **경고색**으로
표시하고, 보고서에는 다음 문장이 자동으로 들어갑니다.

> _분류: 외부 Agent (MCP) — 앱의 분류 프롬프트를 거치지 않았습니다. 인용문은 원문 그대로입니다._

**원문 보존은 경로와 무관하게 유지됩니다.** Agent 경로도 AI 경로와 **같은 조립 함수**를 통과합니다.
인용문은 DB 원문에서 번호로 조립되므로, Agent 역시 없는 말을 만들어 넣을 수 없습니다. 지시가 아니라
구조로 막혀 있습니다.

MCP로 나가는 지원서·설문 응답에도 개인정보 마스킹이 적용됩니다. 코디네이터 화면은 원문 그대로입니다 —
코디네이터는 제출된 내용을 볼 권한이 있습니다.

## 8. 검증 방법

심사위원이 직접 확인할 수 있는 항목입니다.

```bash
# 테스트 96개 전체
cd app && npm test --workspace backend

# 개인정보 미전송 검증
node --import tsx --test src/utils/redaction.test.ts

# AI Pro 규격 준수 검증 (로컬 mock 대상)
node --import tsx --test src/services/llm/aiProProvider.test.ts

# 인용문 원문 보존 검증 — AI 경로와 Agent 경로 모두
node --import tsx --test src/services/llm/surveyVoc.test.ts

# Agent가 넘긴 점수의 입력 검증
node --import tsx --test src/schemas/contracts.test.ts
```

**화면 시연 포인트** — AI 스위치를 껐다 켜며 같은 작업을 두 번 실행하면, AI가 없어도 업무가
중단되지 않는다는 것을 그 자리에서 보여줄 수 있습니다. 거버넌스 항목에서 가장 강한 장면입니다.
