어떤 기능이 AI를 쓰고, 어떤 기능이 쓰지 않는가

프로그램 운영 자동화 시스템의 기능을 하나씩 설명합니다. 각 기능마다 AI가 판단하는 부분과 코드가 실행하는 부분을 나눠 적었습니다. 두 칸으로 나뉜 이유는, 그 구분이 이 시스템의 설계 원칙 그 자체이기 때문입니다.

코드가 실행

AI가 없으면 규칙 기반 채점으로 순위를 냅니다. 선정은 멈추지 않습니다.

코드가 실행

연동을 만들지 않고 연동한 사례입니다. Confluence API 키도, 우리 쪽 코드도, 배포도 필요 없습니다 — 서로 다른 두 MCP 서버를 Agent가 이어 줍니다.

AI를 켜고 끄는 방식

이중 잠금

① 서버 설정과 ② 관리자 스위치를 둘 다 통과해야 AI가 호출됩니다. 기능별로 따로 켤 수 있고, 기본값은 전부 꺼짐입니다.

어정쩡한 상태를 만들지 않습니다

AI 제공자가 설정되지 않았는데 스위치를 켜려 하면 거부합니다. "설정은 켜졌는데 실제로는 다른 방식으로 도는" 상태가 생기면 아무도 눈치채지 못합니다.

AI에 무엇을 보내지 않는가

사내 규정상 AI에 개인정보를 보내려면 승인이 필요한데 이 앱은 받을 수 없습니다. 그래서 보내지 않는 것을 코드로 강제했습니다.

DB 원문은 그대로입니다. 코디네이터가 보는 화면, 보고서의 인용문, AI를 쓰지 않는 채점은 모두 실제 작성 내용을 씁니다.

사외 AI로 나갈 때는 이름조차 빼고 나갑니다

위 표는 사내 AI Pro 기준입니다. 사외 Claude·ChatGPT가 도구로 읽을 때는 더 엄격해서, 신청자·참여자·상품 수령자 모두 이름과 이메일 자체가 빠지고 신청자 1 같은 핸들만 나갑니다. 모집 메일 미리보기도 주소 목록 대신 수신자 수만 돌려줍니다. 가리는 것이 아니라 항목을 빼므로 되돌릴 수 없습니다.

실제 응답으로 확인했습니다 — 전 프로그램의 신청자·참여자·수령자 조회에서 이름도, @ 문자 하나도 나오지 않았습니다.

판단의 출처를 구분합니다

같은 점수라도 어디서 왔는지에 따라 보장 수준이 다릅니다. 하나로 묶으면 기록이 사실보다 높은 신뢰를 주장하게 됩니다.

되돌릴 수 없는 일에는 확인 단계

메일은 사람이 확정합니다

임직원에게 나가는 메일은 회수할 수 없습니다. 미리보기가 누구에게 무엇이 갈지를 먼저 보여주고, 실제 발송은 별도 확인이 필요합니다. Agent는 준비까지만 할 수 있습니다.

선정도 마찬가지

AI 점수는 순위를 제안할 뿐이고, 확정은 코디네이터가 합니다. 확정 전 미리보기에서 누가 선정될지와 그 이유를 볼 수 있습니다.

설문은 초안까지만

Sally 설문은 만들어두기만 하고 배포하지 않습니다. 임직원에게 나가는 시점은 담당자가 정합니다.
