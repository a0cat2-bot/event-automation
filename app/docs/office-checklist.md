## 1. AI Pro 연결 — 10분

`app/backend/.env` 에서 아래 **세 줄**만 채웁니다. 나머지 항목은 기본값이 이미 들어가 있습니다.

```
LLM_PROVIDER=ai_pro          # 지금은 openai 로 되어 있음 → 반드시 바꿀 것
AI_PRO_API_URL=              # 사내 AI Pro 게이트웨이 주소
AI_PRO_API_KEY=              # 발급받은 키
```

> 변수명 주의: `AI_PRO_SERVICE_KEY` 가 아니라 **`AI_PRO_API_KEY`** 입니다.

**확인 방법**: 백엔드를 띄우고 관리 화면에서 AI 설정을 열면, 공급자가 구성됨으로 표시됩니다.
키가 없으면 기능을 켜는 요청 자체가 409로 거부되므로, 잘못된 상태로 넘어갈 수 없습니다.

### 왜 `openai` 를 그대로 두면 안 되는가

사외 AI를 API로 호출하는 것은 사내 정책 위반입니다. 시연 중에 이 값이 보이면 그 자체로 감점
요인입니다. 키는 이미 비워 두었지만 **공급자 이름이 아직 `openai`** 이므로 반드시 바꿔야 합니다.

## 2. AI 기능 3개 실제 동작 확인 — 20분

스위치는 이미 켜져 있으므로, 키만 들어가면 바로 돌아갑니다.

| 기능 | 확인 화면 | 봐야 할 것 |
|---|---|---|
| 신청 사유 심사 | 참여자 선정 | 점수와 **근거 문장**이 함께 나오는지 |
| 레터 문구 생성 | 레터 미리보기 | 병합 필드가 실제 값으로 치환되는지 |
| 설문 VOC 분류 | 만족도 설문 결과 | **인용문이 원문과 글자 단위로 같은지** |

세 번째가 가장 중요합니다. 인용문은 모델이 아니라 코드가 원문에서 꺼내므로 지어낼 수 없습니다.
이것이 이 시스템의 가장 강한 설계이고, 발표에서 보여줄 지점입니다.

**AI가 실패해도 화면은 멈추지 않습니다.** 심사는 휴리스틱으로, VOC는 "분석 없음"으로 떨어집니다.
실패 화면도 한 번 보아 두면 설명할 때 쓸 수 있습니다.

## 5. 회사에서 확인해야 할 것 (코드 아님) ★

**이것이 개발보다 우선입니다.** 기준을 모르는 채로 만들면 지난번 실패를 반복합니다.

### 5-1. AI Pro 자격증 기준

- 평가 방식이 **시험**인지 **실습 프로젝트 제출**인지
- 제출물이라면 **심사 항목과 배점**
- 기존 업무 산출물을 제출해도 되는지, 지정 과제가 있는지

> 공개 정보로 확인되는 것은 SDS Pro(알고리즘 코딩 검정)와 ProDS(데이터 사이언티스트 시험)뿐이고,
> 둘 다 시험 방식입니다. "실습 프로젝트 제출"과 어긋나므로 반드시 사내에서 확인이 필요합니다.

### 5-2. 사외 AI(Claude/ChatGPT) 연결 가능 여부

에이전트 경로를 쓰려면 확인이 필요합니다.

- 회사 PC에 **Claude Desktop 설치**가 가능한지
- 또는 웹 Claude의 **커스텀 커넥터**를 관리자가 열어 줄 수 있는지
- **익명 핸들 방식이 Data Privacy 기준을 충족하는지** — 이름·이메일은 나가지 않고 `신청자 1`
  같은 핸들만 나갑니다. 다만 이것이 사내 기준을 만족하는지는 **보안팀 판단 사항**입니다.

### 5-3. 사내 Confluence MCP 접근

결과 보고서를 Confluence에 올리는 경로입니다. 이 저장소에는 Confluence 코드가 한 줄도 없고,
**두 MCP 서버를 에이전트가 잇는 구조**이므로 확인할 것은 접근 권한뿐입니다.

- 사내 Confluence MCP 서버의 **주소와 연결 방식** (stdio인지 원격인지)
- 내 계정으로 **쓰기 권한**이 있는지, 어느 공간(space)에 올릴 수 있는지
- Claude 클라이언트에 **두 MCP를 동시에 등록**할 수 있는지

**확인되면 보고서 하나를 실제로 게시해 볼 것.** 성공하면 "서로 다른 두 MCP를 이어 하나의 업무를
끝낸 기록"이 남습니다. 단발 호출 네 개와는 성격이 다르고, 에이전트 활용을 보는 심사에서는
지금 이 시스템에서 가장 내세울 만한 지점입니다.

## 6. 에이전트 경로 (사외 AI 연결)

집에서 이미 검증을 마쳤습니다. 회사에서는 5-2가 허용될 때만 진행합니다.

**검증된 사실**
- MCP 툴 26개 정상 연결
- 전 프로그램 × 신청자·참가자·수령자 조회에서 **신원 유출 0건** (이메일 `@` 문자조차 없음)
- 백엔드가 꺼져 있으면 예외 대신 읽을 수 있는 오류 문자열을 반환

**연결 방법** (Claude Desktop 기준)

`~/Library/Application Support/Claude/claude_desktop_config.json` 에 아래를 추가하고 앱을 재시작합니다.

```json
{
  "mcpServers": {
    "event-automation": {
      "command": "npx",
      "args": ["tsx", "src/index.ts"],
      "cwd": "<저장소 경로>/app/mcp-server",
      "env": {
        "MCP_TRANSPORT": "stdio",
        "BACKEND_API_URL": "http://localhost:3000/api/v1"
      }
    }
  }
}
```

백엔드가 3000번에서 돌고 있어야 합니다: `npm --prefix app run dev --workspace backend`

**중요**: 이 경로는 **API 키가 필요 없습니다.** 앱이 외부를 호출하는 것이 아니라, 사람이 승인된
Claude를 열고 Claude가 앱의 툴을 호출하는 구조이기 때문입니다.
